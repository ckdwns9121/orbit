# Orbit 제품 문제 정의

> AI 시대의 개인 업무 연속성 시스템은 어떤 문제를 해결해야 하는가?

작성일: 2026-08-05

## 문서 목적

이 문서는 Orbit이 해결하려는 문제의 본질을 기록한다. 개별 기능의 목록이 아니라 제품 방향과 우선순위를 판단하는 기준으로 사용한다.

## 한 문장 문제 정의

AI와 여러 업무 도구를 오가며 동시에 많은 일을 처리하지만, 작업의 현재 상태를 외부화하고 중단된 맥락을 복구하며 완료 후의 결과를 남길 시스템이 없다.

## 사용자가 겪는 문제

### 1. 여러 작업을 동시에 진행한다

AI를 활용하면 과거보다 더 많은 작업을 병렬로 시작하고 실행할 수 있다. 그러나 사람의 주의력은 여전히 한 번에 하나의 작업에 집중한다. 실행 가능량은 늘었지만 진행 중인 작업을 기억하고 조율하는 부담도 함께 커졌다.

### 2. 컨텍스트 스위칭 과정에서 작업이 유실된다

- A, B, C 작업을 오가다가 B 작업의 존재 자체를 놓친다.
- A, B, C를 진행하던 중 긴급한 D 작업이 들어오면 기존 작업을 어디까지 했는지 잊는다.
- 중단된 작업을 다시 열어도 관련 대화와 코드, 결정, 다음 행동을 재구성하는 데 시간이 든다.

이 문제는 개인의 기억력이나 집중력 부족이 아니다. 중단 시점의 작업 상태가 시스템에 보존되지 않기 때문에 발생한다.

### 3. 실제 작업과 티켓 관리가 분리되어 있다

Jira 티켓의 상태 변경, 작업 결과 기록, PR·커밋 연결은 실제 업무와 별도의 행정 작업으로 남는다. 그 결과 실제 진행 상황과 티켓 상태가 쉽게 어긋나며, 티켓은 신뢰할 수 있는 현황판이 되지 못한다.

### 4. 완료한 업무가 학습 자산으로 남지 않는다

작업이 끝나면 무엇을 결정했고, 어떤 시행착오가 있었으며, 다음에는 무엇을 다르게 해야 하는지가 기록되지 않는다. 완료는 업무 흐름의 끝이 되고, 결과와 맥락은 시간이 지나면서 사라진다.

### 5. Slack 요청이 구조화된 업무로 전환되지 않는다

온콜이나 긴급 요청이 Slack 대화 속에 머문다. 진행 상황이나 과거 요청을 확인하려면 매번 채팅을 다시 검색해야 하며, 누락 여부도 사람의 기억에 의존한다.

## 문제의 본질

핵심 문제는 할 일이 많다는 것이 아니라, 여러 도구와 AI 세션에 흩어진 **업무 상태의 연속성**이 보장되지 않는다는 것이다.

현재 업무 환경에는 세 가지 연결 고리가 부족하다.

### 업무의 입구

Jira, Slack, GitHub, AI 세션과 직접 입력에서 발생한 신호를 하나의 관리 가능한 작업으로 수집하고 정규화해야 한다.

### 중단과 재개의 연결

작업을 전환할 때 현재 맥락을 체크포인트로 남기고, 나중에 다음 행동부터 바로 재개할 수 있어야 한다.

### 업무의 출구

완료 시 Jira 상태, PR·커밋, 공유 내용, 주요 결정과 회고가 실제 작업의 부산물로 함께 갱신되어야 한다.

## Orbit의 제품 관점

Orbit은 또 하나의 할 일 관리 앱이 아니라 **AI 시대의 개인 업무 연속성 시스템**이어야 한다.

제품이 보장해야 할 핵심 가치는 다음과 같다.

> 어떤 작업도 고아가 되지 않으며, 중단된 작업은 맥락과 함께 다시 시작할 수 있고, 완료된 작업은 결과와 학습을 남긴다.

Orbit이 관리해야 하는 핵심 단위는 단순한 티켓이 아니라 **재개 가능한 작업 상태**다.

## 재개 가능한 작업 상태

각 작업에는 최소한 다음 정보가 있어야 한다.

- 작업의 목적과 완료 조건
- 현재 상태와 우선순위
- 마지막으로 수행한 일
- 바로 이어서 할 수 있는 다음 행동
- 현재 막힌 이유와 재개 조건
- 관련 Jira 티켓, Slack 대화, PR, 커밋, AI 세션
- 진행 중 만들어진 주요 결정과 결과물
- 중단된 시점과 다시 확인해야 할 시점

작업 전환은 단순한 화면 이동이 아니라 다음 상태 전이로 다뤄야 한다.

```text
A 작업 진행
  ↓
긴급 D 작업 유입
  ↓
A의 현재 상태와 다음 행동을 체크포인트로 저장
  ↓
D 처리
  ↓
중단된 작업 목록에서 A를 맥락과 함께 재개
```

## 핵심 제품 흐름

Orbit의 전체 흐름은 네 단계로 정리할 수 있다.

```text
수집 → 집중·전환 → 재개 → 종료·학습
```

### 수집

Slack 온콜, Jira 티켓, GitHub 활동, AI 세션과 직접 입력을 작업으로 통합한다.

### 집중·전환

지금 집중할 작업을 명확히 하고, 다른 작업으로 이동할 때 중단되는 작업의 체크포인트를 남긴다.

### 재개

잊힌 작업과 중단된 작업을 적절한 시점에 다시 제시하고, 저장된 다음 행동과 관련 맥락에서 바로 시작하게 한다.

### 종료·학습

완료 상태를 외부 도구와 동기화하고, 결과·결정·공유 내용·회고를 자동으로 정리해 다음 업무에 재사용할 수 있게 한다.

## 제품 판단 기준

새 기능을 검토할 때 다음 질문에 답해야 한다.

1. 작업이 대화나 도구 속에서 유실되는 것을 줄이는가?
2. 작업을 중단할 때 현재 맥락과 다음 행동을 보존하는가?
3. 사용자가 중단된 작업을 적절한 시점에 다시 발견하게 하는가?
4. 실제 업무 진행과 Jira·Slack·GitHub 상태 사이의 수작업을 줄이는가?
5. 완료한 업무에서 결과와 학습을 남기는가?

이 질문에 기여하지 않는 기능은 Orbit의 핵심 문제보다 후순위로 둔다.

## 해결해야 할 중심 질문

Orbit은 단순히 “내 할 일이 무엇인가?”에 답하는 제품이 아니다. 다음 질문에 답해야 한다.

> 지금 무엇에 집중해야 하고, 중단하더라도 어떻게 맥락을 잃지 않으며, 끝난 작업에서 무엇을 남길 것인가?
