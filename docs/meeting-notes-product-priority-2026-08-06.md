# Orbit 제품 방향 및 개발 우선순위 회의록

- 일시: 2026-08-06
- 목적: 현재 제품의 핵심 문제를 재확인하고, 해결 방법과 다음 개발 우선순위를 결정한다.
- 검토 관점: 사용자 문제·제품 설계·제품 우선순위
- 관련 문서: [제품 문제 정의](product-problem.md), [제품 솔루션 제안](product-solution.md)

## 결론

Orbit은 현재 **여러 업무 도구의 정보를 한곳에서 찾고 연결하는 제품**으로는 상당한 수준에 도달했다. 그러나 핵심 약속인 **중단된 작업을 잊지 않고 맥락과 함께 다시 시작하는 경험**은 아직 완성되지 않았다.

다음 개발의 중심은 새 커넥터나 범용 AI 기능이 아니라 아래의 폐쇄 루프를 만드는 것이다.

> 수집 → 집중 → 중단 기록 → 재발견 → 재개 → 완료 및 학습

다음 스프린트의 제품 문장은 **“중단된 일을 잊지 않고 30초 안에 다시 시작한다”**로 정한다.

## 1. 현재 문제

### 문제의 본질

AI 덕분에 동시에 실행할 수 있는 작업은 늘었지만 사람의 주의력은 그대로다. Task, AI 세션, Jira, Slack, GitHub, Calendar에 작업 상태와 근거가 분산되어 있어, 작업이 중단될 때 사용자가 기억에 의존해 맥락을 복구한다.

따라서 Orbit이 관리해야 할 단위는 단순한 할 일이나 티켓이 아니라 다음 정보가 포함된 **재개 가능한 작업 상태**다.

- 지금까지 한 일
- 마지막으로 내린 결정
- 다음 행동
- 막힌 이유와 재개 조건
- 관련 AI 세션·Jira·Slack·PR·커밋
- 중단 시각과 다시 확인할 시점

### 반복되는 사용자 상황

1. 여러 작업과 AI 세션을 시작한 뒤 긴급 요청이 들어오면 기존 작업의 존재나 진행 지점을 놓친다.
2. 작업을 다시 열어도 대화, 코드, 티켓, PR을 다시 찾으며 맥락을 재구성한다.
3. 실제 진행 상태와 Orbit Task, Jira, PR 상태가 서로 달라 별도의 관리 업무가 생긴다.
4. Slack 요청이 대화에 머물러 Task로 구조화되지 않고 후속 조치가 누락된다.
5. 작업 완료 후 결과, 결정, 시행착오와 회고가 남지 않는다.

### 현재 제품의 상태

이미 해결한 부분:

- Dashboard에서 오늘 작업, 어제 완료 작업, 열린 PR, 리뷰 요청, 오늘 일정을 확인할 수 있다.
- Task 상태, 집중 작업, 체크포인트, 다음 행동을 관리할 수 있다.
- Jira, GitHub, AI 세션, Slack, Confluence, Calendar 컨텍스트를 조회하고 연결할 수 있다.
- AI Chat과 Task 자동 연결 제안, 목표 시간 알림이 존재한다.

아직 부족한 부분:

- 새 요청을 지속적으로 수집하고 중복을 제거하는 Inbox 흐름
- 중단 시 자동 체크포인트 초안과 막힌 이유·재개 조건 기록
- 작업을 다시 발견하고 관련 맥락을 한 번에 여는 재개 경험
- 외부 데이터의 마지막 동기화 시각과 실패 상태 표시
- Orbit 상태와 Jira 등 외부 상태의 승인형 양방향 동기화
- 완료 시 결과와 회고를 남기는 종료 흐름

## 2. 해결 방법

### A. 재개 브리핑

Dashboard 최상단에 `이어서 시작` 영역을 만든다.

- 마지막 집중 작업의 체크포인트와 다음 행동 표시
- 중단 시각과 방치 기간 표시
- `재개` 버튼으로 focus 전환
- 연결된 AI 세션, Jira, PR, Slack 근거를 함께 열기
- 오래 멈춘 review·ai_running·blocked 작업을 재점검 큐에 표시

이 기능이 Orbit의 가장 중요한 차별점이다.

### B. 체크포인트 구조화 및 자동 초안

- focus 이탈뿐 아니라 blocked 전환에도 기록을 요구한다.
- `막힌 이유`, `재개 조건`, `중단 시각` 필드를 추가한다.
- AI 세션의 최근 요청, 최근 커밋, Jira 상태를 바탕으로 체크포인트 초안을 만든다.
- 사용자는 빈 문장을 작성하는 대신 초안을 확인하고 수정한다.

### C. 데이터 신뢰성 표시

- Jira, GitHub, Slack, Calendar 등 소스별 마지막 동기화 시각을 보여준다.
- 오래된 캐시는 명확히 표시하고 즉시 새로고침할 수 있게 한다.
- 앱이 다시 활성화될 때 TTL이 지난 소스만 동기화한다.
- 권한 만료, API 제한, 부분 성공, 실패 원인을 구분한다.

### D. 상태 변경은 실행보다 제안 우선

- AI 세션 완료가 곧 Task 완료를 의미하지 않도록 한다.
- 모든 세션이 끝나면 Task를 자동 완료하지 않고 `내 확인 필요`로 제안한다.
- Jira 전환, Slack 공유 등 외부 쓰기는 미리보기와 사용자 승인 후 실행한다.
- 사용자 조작이 자동화보다 항상 우선한다.

### E. 완료 시트

Task를 완료할 때 다음 내용을 자동으로 초안 작성한다.

- 한 일과 결과물
- 주요 결정
- 연결된 PR·커밋·Jira
- 남은 위험
- 다음에 다르게 할 점

연결된 Jira가 있으면 승인 후 Done 전환을 실행하고, 실패하면 Orbit 완료는 유지하면서 재시도할 수 있게 한다.

### F. 통합 Inbox

새로 할당된 Jira, 저장된 Slack 메시지, 연결되지 않은 AI 세션을 제안 항목으로 모은다. 자동 Task 생성 대신 다음 세 가지 행동만 제공한다.

- 새 Task로 채택
- 기존 Task에 연결
- 무시

## 3. 개발 우선순위

### P0 — 핵심 사용 루프 완성

1. 재개 브리핑과 원클릭 재개
2. 막힌 이유·재개 조건·중단 시각 저장
3. 체크포인트 자동 초안
4. 소스별 마지막 동기화 시각과 오류 상태 표시
5. 핵심 행동 계측

P0 성공 기준:

- 재개 버튼을 누른 뒤 필요한 맥락에 30초 안에 도달한다.
- 집중 작업 변경 시 체크포인트 저장률이 95% 이상이다.
- 7일 이상 방치된 open Task의 비율이 감소한다.
- 중단 작업의 24시간 내 재발견률을 측정할 수 있다.

### P1 — 수작업 감소

1. 통합 Inbox 및 중복 제거
2. Jira 상태의 승인형 양방향 동기화
3. Slack 메시지의 승인형 Task 전환
4. 완료 시트와 결과 패키지

P1 진입 조건:

- P0 재개 흐름이 실제 사용자에게 주 2회 이상 반복 사용된다.
- 데이터 신선도와 동기화 실패율을 측정할 수 있다.
- Task와 외부 항목의 연결 규칙이 안정화된다.

### P2 — 장기 학습 자산화

1. 완료 작업의 결정·시행착오 검색
2. 주간 회고 및 반복 패턴 요약
3. 유사 작업의 체크리스트와 템플릿 추천
4. 신뢰가 확인된 저위험 작업의 선택적 자동화

## 4. 지금 추가하지 않을 기능

- Notion, Linear, Teams 등 추가 커넥터
- 범용 AI Chat 및 멀티모델 기능 확대
- 무승인 Jira·Slack 자동 쓰기
- 팀 관리자 대시보드와 조직 기능
- 모바일 앱과 클라우드 동기화
- 커밋 수 중심의 생산성 점수와 게임화
- 별도의 Calendar 대체 기능

현재 단계에서 이 기능들은 핵심 가치 검증을 늦추고 제품 면적과 운영 리스크만 키울 가능성이 높다.

## 5. 제품 지표

North Star 후보는 **주간 재개 성공 작업 수**로 정한다.

보조 지표:

- 체크포인트가 있는 중단 작업 비율
- 체크포인트 저장 후 7일 내 재개율
- 재개 후 24시간 내 상태 진전율
- 7일 이상 방치된 open Task 비율
- Inbox 제안 채택률과 중복률
- 커넥터별 동기화 실패율과 데이터 평균 나이
- 완료 시트 작성률
- Orbit Done과 Jira Done의 불일치 건수

## 6. 결정사항

- 다음 개발은 기능 확장보다 재개 루프 완성에 집중한다.
- 자동 상태 변경과 외부 쓰기는 제안 및 승인형을 기본으로 한다.
- Dashboard는 성과 차트보다 오늘 행동과 중단 작업 재발견을 우선한다.
- 데이터의 마지막 동기화 시각과 오류 상태를 제품 전반에 표시한다.
- Chat과 추가 커넥터는 P0 완료 전까지 유지보수 수준으로 동결한다.

## 7. 액션 아이템

| 우선순위 | 액션 | 완료 조건 |
|---|---|---|
| P0-1 | 재개 브리핑 UX와 상태 모델 설계 | 마지막 작업·체크포인트·다음 행동·중단 시각을 한 화면에 표시 |
| P0-2 | `blockedReason`, `resumeCondition`, `pausedAt` 데이터 모델 추가 | blocked 전환과 focus 이탈 시 구조화된 기록 저장 |
| P0-3 | 체크포인트 자동 초안 구현 | AI 세션·커밋·Jira 근거로 수정 가능한 초안 생성 |
| P0-4 | 동기화 신선도 표준화 | 각 소스의 마지막 동기화·실패·stale 상태 표시 |
| P0-5 | 재개 성공 이벤트 계측 | 주간 재개 성공 작업 수와 방치 작업 비율 산출 가능 |
| P1 | 통합 Inbox 및 승인형 Jira write-back 설계 | 중복 방지와 실패 재시도 정책 포함 |
