# Orbit 제품 원칙

- 상태: Accepted
- 적용 범위: Orbit 전체 제품
- 근거: [제품 문제 정의](../product-problem.md), [업무 연속성 PRD](../prd/prd-orbit-work-continuity.md)

## 1. Task가 업무의 기준점이다

Jira 티켓, Slack 메시지, GitHub PR·커밋, Calendar 일정과 AI 세션은 Task에 연결되는 근거다. 외부 객체 하나가 사라지거나 동기화에 실패해도 Task의 목적·상태·다음 행동은 유지되어야 한다.

## 2. 사용자의 주의력은 한 번에 하나만 점유한다

진행 중인 Task는 여러 개일 수 있지만 현재 집중 중인 Task는 하나만 허용한다. 다른 작업으로 이동할 때는 기억에 의존하지 않도록 현재 지점과 다음 행동을 보존한다.

## 3. 자동화는 설명하고 승인을 구한다

AI와 외부 상태는 연결·우선순위·상태 전이를 제안할 수 있다. Task 또는 외부 시스템을 변경하는 동작은 사용자가 결과를 이해하고 승인할 수 있어야 한다.

## 4. 출처가 없는 컨텍스트를 사실처럼 만들지 않는다

AI 응답, 자동 연결, 완료 기록은 출처와 신선도를 드러낸다. 회고를 건너뛰거나 외부 조회가 실패한 경우 이를 빈 성공이나 생성된 사실로 대체하지 않는다.

## 5. 로컬 데이터는 독립적으로 사용할 수 있어야 한다

네트워크가 없거나 외부 API가 실패해도 로컬 Task와 저장된 컨텍스트를 읽고 관리할 수 있어야 한다. 외부 캐시는 원본과 마지막 성공 시각을 구분한다.

## 6. 완료는 삭제가 아니라 증거가 남는 종료다

Task 완료 시 결과, 판단, 남은 위험, 회고와 연결 근거를 함께 보존한다. 사용자가 회고 작성을 건너뛰면 건너뛴 사실을 기록하되 내용을 꾸며내지 않는다.

## 7. 안전한 실패를 정상 흐름으로 취급한다

외부 쓰기, 동기화, DB 전이는 실패·재시도·재기동을 고려한다. 부분 성공을 완전한 성공으로 표시하지 않으며, 충돌 시 최신 사용자 변경을 덮어쓰지 않는다.
