## Background

Task를 단순히 `done`으로 바꾸면 어떤 결과를 만들었고 어떤 Jira·PR·커밋·AI 세션이 근거였는지 시간이 지나며 사라진다. 상태 변경과 기록 저장을 따로 실행하면 일부만 성공해 완료 목록과 성과 기록이 불일치할 수 있다. 반대로 모든 필드를 강제하면 작은 작업의 완료 마찰이 커진다.

## Decision

완료 record 생성이 Task `done` 전이와 focus 해제를 원자적으로 발생시키도록 한다. 당시의 정제된 evidence를 snapshot으로 보존한다. 사용자는 회고를 명시적으로 건너뛸 수 있으며, 이때는 건너뛴 사실만 기록하고 결과를 생성하지 않는다.

## Options

| Option | Pros | Cons |
| --- | --- | --- |
| 완료 episode + 원자적 trigger | 상태와 성과 근거가 항상 일치하고 검색 가능함 | schema와 완료 UI가 필요함 |
| Task 상태만 done | 빠르고 단순함 | 결과·결정·근거를 잃음 |
| 상태와 회고를 비동기 저장 | UI 응답이 빠름 | 부분 성공과 복구 불일치 가능 |

**최종 결정:** 완료 episode가 성공해야만 done으로 전이하며, skip도 감사 가능한 명시적 값으로 기록한다.
